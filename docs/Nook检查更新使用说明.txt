Nook · GitHub 检查更新与一键更新

适用范围
本功能加入 0.1.24 预览版；下载以 GitHub 发布页实际资产为准。完成后台检查不代表已安装或已完成真实升级验收。
原先的 0.1.23 安装包没有这个入口，需要先手动安装一次包含本功能的完整发布包。

使用方法
1. 打开「设置 → 关于与更新」。打开页面本身不会联网或自动安装。
2. 点击「检查更新」。软件只查询 lta24131-hub/mori-desk 的 GitHub Releases。
3. 有可安装的新版本时，显示版本、更新说明和下载大小。
4. 保存正在编辑的信息，点击「下载并重启更新」。下载期间仍可取消。
5. 安装器先展开并验证新版本，准备好后才请求正常退出 Nook。
6. 通过原有保存流程后，软件备份当前图库数据库、画布记录、贴图清单和允许备份的设置，再退出。
7. 安装完成后重新打开 Nook；保留旧版程序和现有素材。

公开仓库
仓库公开后，检查和下载都无需 GitHub 账号或令牌；不会把密钥嵌入程序。
软件不会自动把你的素材、设置、截图或日志上传到 GitHub。
公开代码不等于所有第三方组件均可任意商用；画布和滚动截图组件须分别遵守随附许可。

版本范围
当前项目使用预览发布，因此默认勾选「包含预览版本」。关闭后只查正式版。
只接受数字版本高于当前版本、包含 Nook-Setup.exe 且校验信息齐全的发布。
只上传源代码或尚未上传完整安装包的发布不会作为可安装更新。
安装文件名、程序版本和发布标签必须对应；不自动降级。

安全与失败处理
- 使用 HTTPS，并校验 GitHub 提供的 SHA-256 摘要或发布内 SHA256SUMS.txt。
- 下载时校验大小和摘要，执行前再校验摘要、产品身份和版本；不执行不完整的文件。
- SHA-256 是完整性校验，不代表安装包已通过商业代码签名。
- 不强制结束软件；导入未完成、画布保存失败、备份失败或用户取消时保持旧版运行。
- 更新器使用独立版本目录，不覆盖或删除旧目录、素材原件、画布图片或贴图原图。
- 只迁移已确认属于当前 Nook 的快捷方式与既有自启动项，不新开自启动、不改默认应用。
- 新版必须完成图库初始化并显示主窗口，返回与本次进程匹配的启动确认，才标记更新成功；仅有进程存活或错误弹窗不算成功。
- 新程序未能确认启动时尝试正常关闭本次新版、恢复旧入口并打开旧版，不强制结束进程。启动确认仍不等于所有功能已通过完整验收。
- 有另一个 Nook 窗口仍在运行时会暂停更新，不自动关闭其他窗口。

备份位置与边界
更新会话位于 %LOCALAPPDATA%\MoriDesk\updates\<会话编号>。
成功的元数据备份在其中的 metadata-backup；complete.json 最后写入，表示备份完成。
备份有体积上限，只用于记录恢复，不包含全部原始素材、画布图片、贴图图片或浏览器凭据。
它不能代替「图库备份」或换电脑前的完整数据备份。原始数据仍保留在原位置。
便携版请先使用安装包安装为标准版本；自动安装协调不接受随意位置的程序路径。

浏览器插件
这是主程序更新入口。新版程序随附插件后，仍在「设置 → 浏览器收藏」里使用现有的一键更新。
首次安装、浏览器权限变化或非常旧的插件，仍需浏览器中的确认；不绕过浏览器安全限制。

发布者检查
发布标签应与程序集和安装器版本一致，例如 v0.1.24-preview 对应 0.1.24.0。
上传完整 Nook-Setup.exe 与 SHA256SUMS.txt 后再发布；不要覆盖已经发布的同版本二进制。
package.ps1 会生成安装器、便携包、使用指南的校验清单，并排除本机配对/授权文件。
截图组件必须带完整运行时、许可证和对应源码，不能只发布一个 Mori.exe。

本次验收边界
按用户要求，本轮仅后台开发、隔离测试和发布核对；未启动真实更新安装器、未关闭正在用的 Nook、未进行真实滚动截屏。
本版作为预览版提供，真实更新过程、保存退出、重开和滚动截图的桌面行为仍待在其他电脑验证；请保留旧版和完整数据备份。
