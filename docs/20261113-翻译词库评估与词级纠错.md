# 翻译词库评估与词级纠错

本轮针对“接词库是否有帮助、是否影响速度”评估并实现。实体机只编辑和编译；所有程序执行、模型对照与在线翻译在 NookTester 虚拟机完成。未安装实体版、未发布 GitHub。

## 采用与不采用的方案

- 采用 [SymSpell 6.7.3](https://github.com/wolfgarbe/SymSpell/tree/v6.7.3) 的单次编辑候选查找。完整英文词表用于排除已经合法的英文词；自动纠正的目标只限经过筛选的界面词汇。取消“高频词加普通虚词就自动修改”的初稿，因为它会把可能是人名的 `michaei` 改为 `michael`。
- 不采用整段拼写重写，不安装 Python 或大语言纠错模型。代码使用 MIT 许可；Google Books Ngram 和 SCOWL 词表的独立许可、来源、通知随软件打包。
- 保留 PP-OCRv5。独立比较 v6 Tiny 后，核心错误没有改善，短截图反而更慢；v6 Small 仅下载准备，未运行，不能据此评价其效果。

## 最终处理路径

`原始 OCR（保留） → 带词级证据的翻译输入副本 → 专名保护与完整句子翻译 → 原坐标排版`

1. 识别分数明确区分模型、未知来源和用户确认。旧 Windows 结果不冒充高可信度模型结果；Tesseract 使用词级分数，进程通信和缓存保留来源。
2. 每个词必须精确对应当前段落的一个 token，且只属于一个区域。整行平均分、重叠归属、无法对齐的顺序均不用于自动纠正。
3. 只对特定分数范围内的模型词尝试候选，再要求唯一候选、审核过的界面词和有限的 I/l/i 字形混淆。短缩写另要求明确的局部技术搭配；分数只是门槛，并不是正确性的证明。
4. URL、邮箱、路径、编号、标识符、大小写专名、合法词与手动修改保留。连字符整体词没有独立分数时也保留。原 OCR、复制文字、坐标和共享缓存都不改。
5. 准备后的同一副本进入专名保护、翻译、名称校验和缓存；避免 `OpenAl` 在纠错前被专名规则提前跳过。图片翻译缓存版本更新为 `indexed-regions-v12-evidence-lexicon`。
6. 所选文本只有字符串，没有可对齐的词分数，因此只合并物理换行，不再猜测 Al/AI。取消或关闭窗口会终止准备，并阻止晚到结果进入翻译或渲染。
7. 没有可纠正模型词时同步快速返回；需要词库时在后台准备。词库按需加载并复用，词库阶段不新增网络请求或 OCR 调用。

## 模型实测

固定两张原始英文截图，逐个模型、单进程顺序处理。v5 使用生产单块预处理；v6 使用上游推荐预处理，所以比较的是完整识别流程，不是单变量模型实验。以下均为软件模拟虚拟机的单次时间，不能外推实体机速度。

| 场景 | v5 | v6 Tiny |
| --- | ---: | ---: |
| 689×77 短卡 | 29.51 秒 | 50.56 秒 |
| 1049×255 Craft | 70.73 秒 | 51.72 秒 |
| 处理两图的进程累计峰值工作集 | 380.0 MiB | 439.1 MiB |

两套模型仍把 `No AI for now` 识别成 `No Al for now`，外链图标仍误成 λ / 7 / π。错误 Al 的分数从 v5 的 0.8046 上升到 Tiny 的 0.9966，说明高置信度不等于正确。Tiny 的短边 736 预处理会明显放大扁长截图，模型文件更小也不保证内存和延迟更小。

## 初轮词库测量及真实链路

报告 480 中，词库、置信度、上下文和 Tesseract 分数合约检查通过。初轮扫光检查发现测试仍假定翻译入口同步执行；随后增加无候选快速返回，并增加准备阶段取消的专项验证。最终结果单独记录在本轮证据目录，不把初轮失败报告改成通过。

初轮词库测试测得：首次加载与首次准备 1145.5 毫秒，后续小段平均 0.595 毫秒，100 段共 400 词 62.15 毫秒，高分词快速跳过 0.308 毫秒；额外保留托管内存 6,909,744 字节。它们来自较慢的虚拟机，也不是 OCR 或整个截图翻译的耗时/总内存。

报告 481 使用真实 900×64 原图、一次共享 OCR 验证生产链路：真实模型分数传入，输入副本将技术搭配中的 Al 修正为 AI，原文与坐标保持不变。腾讯完成翻译与绘制，未放置数为 0。Google 请求约 12 秒超时，未计为在线通过，未自动切换提供方，也未改代理或网络配置。
