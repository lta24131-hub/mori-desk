# 桌面收藏通知候选

用户确认需要桌面右下角通知，切到其他软件后仍能看到。此次将拖图和右键收藏的进度、结果交给 Nook 的桌面通知窗口，网页内提示作为不可用时的回退。

## 行为

- 主屏工作区右下角，避开任务栏；不抢焦点、不占任务栏，窗口置顶。
- 保存中在同一卡片更新为成功、失败、结果未确认或重复图片选择。重复选择完成后复用卡片；只有真实保存结果成功才显示成功。
- 显示名称、分类，以及可安全取得的小型预览；跨域图片无法生成预览时使用状态图标，不额外下载原图。
- 成功保留 7 秒，失败和选择保留 15 秒；悬停暂停消失。最多三张卡片，用户关闭的提示不会被迟到结果重新打开。
- 保存与通知冷启动并行。通知失败不重试收藏、不覆盖真实保存结果。原生连接不可用时，通知不争用用于收藏的 HTTP 备用连接。
- 所有卡片消失后，临时通知进程约 10 秒自动退出。不会初始化图库或常驻加载媒体组件。
- 扩展候选版本 0.2.30，身份 key 和权限列表保持不变，没有新增 Chrome 通知权限。

## 验证范围

仅在专用 Windows 虚拟机使用隔离配置和合成数据测试；未操作实体机 Nook、浏览器或真实图库。原生检查通过真实 native messaging 输入/输出启动本机接收进程，再由独立通知进程显示结果；浏览器 DOM 流程用隔离的无头浏览器和模拟保存响应验证。

这不是已安装 Chrome 插件到真实图库的全链路验收，也未实测多显示器切换、混合 DPI 或独占全屏应用。当前定位策略是主屏右下角。

首轮发现新通知进程冷启动的显示确认时限太短；调整有界等待，并补充真实原生消息进程、前台焦点保持及提示结束后进程退出检查。实际收藏不等待通知冷启动。另修正右键收藏转入后台后仍只寻找当前浮层的问题，避免漏接结果或留下更新忙碌状态。

## 最终结果（2026-11-05）

- 浏览器相关回归：112 项通过、0 项失败、3 项跳过，覆盖收藏反馈、收藏恢复、连接、运行时、更新和主题。报告：`latest-desktop-js-333.json`。
- 最终原生检查：151 项通过、0 项失败，包含真实 native messaging 子进程、通知窗口位置和属性、前台焦点保持、状态替换、关闭以及通知进程自动退出。报告：`latest-desktop-native-343.json`。
- 最后调整等待时限后，受影响的浏览器通知与连接检查再次复测：52 项全部通过。报告：`latest-desktop-js-343.json`。
- 通过虚拟机桌面实际观察到任务栏上方的“正在收藏”卡片；切换到资源管理器后发送成功状态，原生接收确认成功。之后观察到卡片正常消失。成功状态外观和退出由原生窗口测试验证，未将该合成通知展示视为真实收藏验收。
- 早期两轮曾暴露显示确认和通知冷启动超时，已将 IPC 读写等待调整为 5 秒、窗口确认等待为 4.5 秒、扩展通知截止时间为 15 秒；上述最终检查在调整后通过。实际保存和通知启动并行，通知异常不会触发重复保存。
