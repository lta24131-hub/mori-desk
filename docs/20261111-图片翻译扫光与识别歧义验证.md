2026-11-11。本轮全部运行检查在 NookTester 虚拟机完成；实体机只编译源码。未安装实体版、未发布 GitHub。

## 实际复现

用户样例原文：`I keep getting AI responses. I asked for cancellation and refund`。

真实 OCR 输出 `Al responses`（末字母为小写 l），腾讯因此返回“艾尔的回复”。直接对照正确 AI 和错误 Al，以及 auto/en 两种源语言，确认本例错误来自传入翻译的识别歧义。指定英文或补句号没有修好 Al，未采用这些无效重试。

识别框为 `[19,16.5,828.5,37]`，右端落在最后字母内部；原有 2 px 清除边距留下一条竖线。

## 修改

- 截图选区、图片与文字窗口、桌面贴图共用单绘制层扫光。识别前扫选区，识别后只高亮文字区域；译图排版完成后用 320 ms 揭示过渡，不显示识别/翻译中的说明段落。错误和无法排入的反馈仍保留。
- 扫光不接收输入，30 fps 上限；关闭、取消、换语言/服务时释放动画和译图引用。隐藏窗口不等待不可见动画，系统关闭动画时直接完成。文字框重叠不产生高亮空洞，贴图旋转/翻转与图片一致。
- 翻译请求中仅修正 `Al responses`、`Al-generated` 等明确技术搭配；不修改原始 OCR 文本，不替换整句中文。人名、所有格、化学式、URL 与不确定搭配保留。无需额外网络请求；更新图片翻译缓存策略版本。
- 将清除原字范围与译文排版范围分离。纯色背景使用随字号变化、最多 8 px 的水平清除边距，邻近区域继续分隔保护；复杂背景保持原边距。字号、起点和换行不因清除边距而改变。更新贴图排版缓存版本。

## 追加：保留常见英文缩写

用户随后指定 AI 这类缩写可保留英文。图片翻译新增 AI、UI、UX、API、CPU、GPU、PDF、USB 白名单：完整句子仍交给翻译服务，在能确认来源和出现次数时将对应中文展开词还原为缩写；单独的缩写标签不请求翻译。原文的全称、人名、普通大写句子和不明确的对应关系不做替换。扫描时先做字符串检查，普通无缩写段落不会逐项运行正则匹配。

更新图片翻译策略为 `indexed-regions-v10-keep-abbreviations`。桌面贴图保存的译图同时校验排版和翻译策略，避免旧的中文展开词缓存绕过新偏好。

## 继续优化：选中文字一致性与密集图片响应

### 代码检查范围及结果

只检查截图翻译热路径（Translation、ImageTranslation、TextWindow、CaptureWindow、PinStore），目标框架为 .NET Framework 4.x。关键模式检查计数保存在 `performance-scan-counts.json`：

- 同步等待异步操作 0 处；ValueTask 0 处；循环 stackalloc 0 处。
- 无 StringComparison 的字面量 IndexOf / StartsWith / EndsWith 各 0 处；字面量 Contains 0 处；Substring 所在行 3 行。
- HttpClient 构造 1 处，由静态 Lazy 复用；JsonSerializerOptions 构造 0 处。
- ContainsKey 所在行 4 行；整图像素缓冲分配 1 处；GeneratedRegex 0 处（该框架不支持）。

确认需要修改的热路径是 3 个界面入口直接同步排版整幅图片；没有为了检查计数改动低收益字符串、字典操作，也未使用当前框架不支持的 API。

### 改动

1. 整图翻译、翻译所选和手动输入共用缩写保留规则。文字翻译缓存独立升级到 `keep-abbreviations-v1`，避免沿用旧展开词；单独 AI/PDF 等不请求服务。普通文字保持人名拼写和段落，只有 OCR 选字入口使用既有的窄范围 Al/AI 纠偏与软换行合并，原始识别文字不变。
2. 图片排版进入可取消的后台任务。截图、识别窗口和贴图共用一个排版名额，避免同时分配多份整图临时缓冲。排队前复制文字和区域几何；用户校正、换语言、关闭窗口时不会读到新旧混合状态。排队取消不消耗名额，运行中按区域检查取消，结果完成后再次检查。
3. 排版试字号时先检查文字尺寸；已超出区域的字号不再生成逐字轮廓。保留原有轮廓检查、字体选择和最终绘制，未降低输出分辨率或省略文本。
