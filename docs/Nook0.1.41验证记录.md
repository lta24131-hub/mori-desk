# Nook 0.1.41 预览版验证记录

本轮继续检查桌面收藏通知，并将此前尚未发布的图库选择、SVG 启动和手动升级入口修复一并纳入。主程序及安装器 0.1.41.0，浏览器插件 0.2.30。所有运行测试均在专用 Windows 虚拟机、隔离配置及合成素材中执行，未安装或操作实体机 Nook。

## 发现及修复

1. 新通知脚本已被后台引用，但原插件安装白名单漏列该文件。直接加载源码的浏览器测试无法发现安装后依赖缺失。本轮补齐，并从真实随包扩展创建受管理安装，逐项检查脚本及后台 importScripts 依赖。
2. 白名单增加文件后，历史未完成更新的清单长度不能继续按新版文件数判断。保留 0.2.30 以前精确的旧清单兼容，同时拒绝新版遗漏必需文件；旧插件仍在运行时不因新版增加文件而被误判损坏。
3. 连续收藏挤出的进行中提示和自动超时消失的提示，不再视为用户主动关闭，真实完成结果仍可出现；主动关闭继续阻止迟到结果重新弹出。
4. 进度通知失败后直接使用网页结果，避免再次启动同样失败的通知连接。图片预览在同一卡片内复用，状态变化不重复解码。

## 检查方法及限制

基线桌面通知 JavaScript 10 项通过。补充的检查覆盖安装产物依赖、旧更新清单迁移、新版本缺文件拒绝、连续收藏和自动超时后的迟到结果、主动关闭、通知失败时保持真实保存结果。最终使用版本为 0.1.41.0 的主程序执行回归。

原生检查通过真实 native messaging 子进程启动桌面通知，验证显示位置、不抢前台和自动退出。浏览器 DOM 流程采用隔离无头浏览器及模拟保存响应；受管理插件安装使用真实随包脚本和隔离目录。未将这些测试表述为已安装 Chrome 扩展到真实图库的完整端到端验收。

本轮不重复全软件功能和实际安装事务，不覆盖混合 DPI 双屏、独占全屏或长期资源趋势。安装器通过对应安全检查及打包校验；历史测试限制仍适用。

## 性能与测试盲区检查

使用 analyzing-dotnet-performance 的关键路径检查及 test-gap-analysis 的行为到断言映射，范围为本轮通知路径及插件安装更新。检查清单：文化相关 IndexOf 0、StartsWith/EndsWith 0、字符串 Contains 0、Substring 2、阻塞任务相关调用 5、ValueTask 0、stackalloc 0、Regex 0、new HttpClient 0、JsonSerializerOptions 0、string.Format 0、ContainsKey 0、LINQ 调用 4、临时 byte[] 2。阻塞等待位于独立原生消息进程或接收线程，均有时限；最多三张卡片的定时遍历不做未经测量的改写。项目为 .NET Framework 4.8，不直接套用新版 .NET 的 Span 或源生成 API。

现有测试对真实保存结果、关闭、焦点及退出已有保护，但安装依赖和两种迟到结果行为没有对应覆盖；本轮新增检查关闭这些缺口。未执行全面变异测试，不声称全部潜在问题已消除。
