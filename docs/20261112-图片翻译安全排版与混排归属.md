# 图片翻译安全排版与混排归属

2026-11-12，接续同日的整句上下文与可读字号优化。全部运行测试在 NookTester 虚拟机；实体机仅编辑、编译和整理证据。没有安装实体版或发布 GitHub。

## 修复依据

1. 原文字框放不下译文时，旧扩框回退没有验证新增像素，会擦掉旁边未被 OCR 识别的图像。虚拟机报告 443 使用蓝色图像复现失败。
2. 第一版安全回退先取最宽矩形，再向下探测。右下角图像会阻断这个矩形，即便原文字正下方仍有足够空白。报告 452 在新断言上失败，证明需要第二个候选。
3. 原 OCR 用合并框重新收集全部词，会把英文框内的独立中文标签重复归入两段；大小字同底线也可能被拆成标题与正文。报告 445 的基线 5 过、4 失败。
4. 同来源编号列表在初稿中被第一项提前收走，文字虽未丢失，但中间标签的阅读顺序错误。最终实现先对同来源所有块分配词，避免第一块贪心领取后续项目。

## 最终行为

- 原位排版只向经过像素检查的空白扩展，保护相邻 OCR 框、不透明图像和半透明像素。更宽的矩形放不下时，再尝试原宽向下；两者都不可用则保留原图和完整译文。
- 多个识别块保持上游来源归属；同来源拆成编号项后，再按各项行框分配词。选择文字与译文段落使用相同的词集合，保留原坐标，不重新猜字框。
- 大小字同行的额外合并要求底线接近、有足够垂直重叠且横向分离；独立标题、正文、真实重复词仍分别保留。
- 没有需要替换的有效文字时直接返回原图，不先复制整张位图。原图引用、完整文本及无效区域计数保持原语义。
- 排版缓存升级为 `readable-overlays-v9-safe-fallback`，OCR 组件身份、校验与缓存统一为 `rapidocrnet-4.2.0-ppocrv5-ch-screen2x-layout5`。

## 尚未覆盖的边界

- 如果底层 OCR 把整份多行编号文本作为一个不可分词返回，只完整保留一次，不伪造每项的文字框。
- I/l/AI/Al 的字形歧义并未全部消除。只保留明确技术搭配的纠偏，不把人名 Al 一律改写为 AI。
- 大图分块接缝存在需要独立修复的归属边界：两块识别出的中心点可能分别落到对方所有权区域。不能简单扩大阈值，否则会误合并跨块的真实重复词。本轮没有修改分块所有权或宣称所有漏字均已解决。
- 复杂照片背景、模糊小字、极密集表格及服务端语义质量仍需真实样本持续验证；不声称已全面达到微信截图翻译水平。
